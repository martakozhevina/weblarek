# Интернет-магазин «Web-Larёk»
«Web-Larёk» — это интернет-магазин с товарами для веб-разработчиков, где пользователи могут просматривать товары, добавлять их в корзину и оформлять заказы. Сайт предоставляет удобный интерфейс с модальными окнами для просмотра деталей товаров, управления корзиной и выбора способа оплаты, обеспечивая полный цикл покупки с отправкой заказов на сервер.

## Архитектура приложения

Код приложения разделен на слои согласно парадигме MVP (Model-View-Presenter), которая обеспечивает четкое разделение ответственности между классами слоев Model и View. Каждый слой несет свой смысл и ответственность:

Model - слой данных, отвечает за хранение и изменение данных.  
View - слой представления, отвечает за отображение данных на странице.  
Presenter - презентер содержит основную логику приложения и  отвечает за связь представления и данных.

Взаимодействие между классами обеспечивается использованием событийно-ориентированного подхода. Модели и Представления генерируют события при изменении данных или взаимодействии пользователя с приложением, а Презентер обрабатывает эти события используя методы как Моделей, так и Представлений.

### Базовый код

#### Класс Component
Является базовым классом для всех компонентов интерфейса.
Класс является дженериком и принимает в переменной `T` тип данных, которые могут быть переданы в метод `render` для отображения.

Конструктор:  
`constructor(container: HTMLElement)` - принимает ссылку на DOM элемент за отображение, которого он отвечает.

Поля класса:  
`container: HTMLElement` - поле для хранения корневого DOM элемента компонента.

Методы класса:  
`render(data?: Partial<T>): HTMLElement` - Главный метод класса. Он принимает данные, которые необходимо отобразить в интерфейсе, записывает эти данные в поля класса и возвращает ссылку на DOM-элемент. Предполагается, что в классах, которые будут наследоваться от `Component` будут реализованы сеттеры для полей с данными, которые будут вызываться в момент вызова `render` и записывать данные в необходимые DOM элементы.  
`setImage(element: HTMLImageElement, src: string, alt?: string): void` - утилитарный метод для модификации DOM-элементов `<img>`


#### Класс Api
Содержит в себе базовую логику отправки запросов.

Конструктор:  
`constructor(baseUrl: string, options: RequestInit = {})` - В конструктор передается базовый адрес сервера и опциональный объект с заголовками запросов.

Поля класса:  
`baseUrl: string` - базовый адрес сервера  
`options: RequestInit` - объект с заголовками, которые будут использованы для запросов.

Методы класса:  
`get(uri: string): Promise<object>` - выполняет GET запрос на переданный в параметрах ендпоинт и возвращает промис с объектом, которым ответил сервер  
`post(uri: string, data: object, method: ApiPostMethods = 'POST'): Promise<object>` - принимает объект с данными, которые будут переданы в JSON в теле запроса, и отправляет эти данные на ендпоинт переданный как параметр при вызове метода. По умолчанию выполняется `POST` запрос, но метод запроса может быть переопределен заданием третьего параметра при вызове.  
`handleResponse(response: Response): Promise<object>` - защищенный метод проверяющий ответ сервера на корректность и возвращающий объект с данными полученный от сервера или отклоненный промис, в случае некорректных данных.

#### Класс EventEmitter
Брокер событий реализует паттерн "Наблюдатель", позволяющий отправлять события и подписываться на события, происходящие в системе. Класс используется для связи слоя данных и представления.

Конструктор класса не принимает параметров.

Поля класса:  
`_events: Map<string | RegExp, Set<Function>>)` -  хранит коллекцию подписок на события. Ключи коллекции - названия событий или регулярное выражение, значения - коллекция функций обработчиков, которые будут вызваны при срабатывании события.

Методы класса:  
`on<T extends object>(event: EventName, callback: (data: T) => void): void` - подписка на событие, принимает название события и функцию обработчик.  
`emit<T extends object>(event: string, data?: T): void` - инициализация события. При вызове события в метод передается название события и объект с данными, который будет использован как аргумент для вызова обработчика.  
`trigger<T extends object>(event: string, context?: Partial<T>): (data: T) => void` - возвращает функцию, при вызове которой инициализируется требуемое в параметрах событие с передачей в него данных из второго параметра.

## Данные
В приложении используются две основные сущности: товар и данные покупателя.
### Интерфейс товара (IProduct)
Описывает структуру данных отдельного товара в каталоге.
### Интерфейс покупателя (IBuyer)
Описывает данные, вводимые пользователем при оформлении заказа.

### Модели данных
Модели отвечают за хранение данных, полученных с сервера, и работу с ними.

#### Класс CatalogModel
Хранение и работа с полным списком товаров, доступных в магазине, выбор товара для предварительного просмотра.

Конструктор:
`constructor()` - инициализирует пустой массив товаров и пустое состояние для выбранного товара.

Поля класса:
`_items: IProduct[]` — массив всех доступных товаров.
`_preview: IProduct | null` — товар, выбранный пользователем для открытия в модальном окне.

Методы класса:
`setItems(items: IProduct[]): void` — сохраняет массив товаров полученный в параметрах метода.
`getItems(): IProduct[]` — получает (возвращает) массив товаров из модели.
`getItem(id: string): IProduct | undefined` — получает(возвращает) товар по его id.
`setPreview(item: IProduct): void` — сохраняет товар для подробного отображения.
`getPreview(): IProduct | null` — получает (возвращает) товар, выбранный для превью.

#### Класс BasketModel
Управляет списком товаров, которые пользователь планирует купить.

Конструктор:
`constructor()` - инициализирует пустой массив корзины.

Поля класса:
`_items: IProduct[]` — массив товаров, добавленных в корзину.

Методы класса:
`getItems(): IProduct[]` — возвращает массив товаров, которые находятся в корзине;
`add(item: IProduct): void` — добавляет товар, полученный в параметре, в массив корзины;
`remove(id: string): void` — удаляет товар, полученный в параметре, из массива корзины;
`clear(): void` — очищает массив товаров в корзине.
`getTotalPrice(): number` — получает стоимость всех товаров в корзине;
`getCount(): number` — возвращает количество товаров в корзине.
`checkInBasket(id: string): boolean` — проверка наличия товара в корзине по его id, полученного в параметр метода.

#### Класс BuyerModel
Хранит данные покупателя и отвечает за их валидацию перед отправкой заказа.

Конструктор:
`constructor()` - инициализирует объект данных покупателя с пустыми значениями.

Поля класса:
`payment: TPayment` — вид оплаты.
`address: string` — адрес.
`phone: string` — телефон.
`email: string` — email.

Методы класса:
`setData(field: keyof IBuyer, value: string): void` — сохраняет значение в конкретное поле модели. Позволяет обновлять данные частично (например, только телефон), не затрагивая остальные поля.
`getData(): IBuyer` — возвращает объект со всеми текущими данными покупателя.
`clearData(): void` — сбрасывает все поля покупателя.
`validate(): Partial<Record<keyof IBuyer, string>>` — проверяет заполнение полей. Возвращает объект с текстом ошибок для каждого невалидного поля. Если ошибок нет, возвращается пустой объект.

### Слой коммуникации
Отвечает за получение данных с сервера и отправку данных на сервер.

#### Класс ApiWebLarek
Непосредственное взаимодействие с бэкендом магазина.
Он преобразует ответы от сервера в типизированные данные, с которыми удобно работать моделям.

Конструктор:
`constructor(cdn: string, baseUrl: string, options?: RequestInit)` - передает baseUrl и options в родительский класс (через super), а cdn сохраняет в собственном свойстве, чтобы позже «склеивать» ссылки на картинки.

Поля класса:
`cdn: string` — базовый путь до папки с изображениями товаров (чтобы правильно формировать ссылки на картинки).
`baseUrl: string` - базовый адрес сервера  
`options: RequestInit` - объект с заголовками, которые будут использованы для запросов.

Методы класса:
`getProductList(): Promise<IProduct[]>` — запрашивает массив всех товаров с сервера.
`getProductItem(id: string): Promise<IProduct>` — запрашивает данные о конкретном товаре по его уникальному ID.
`orderProducts(order: IOrder): Promise<IOrderResult>` — отправляет данные о заказе (товары и данные покупателя) на сервер и получает результат (ID заказа и сумму).

### Слой представления
Классы, которые необходимы для отображения сайта.

#### Класс Header
Отвечает за отображение шапки сайта: вывод логотипа, кнопки корзины и счётчика товаров в ней. В ответ на клик по кнопке корзины генерирует событие для уведомления Презентера.
Наследуется от базового класса Component.

Данные:
Метод render принимает объект этого типа и через сеттер обновляет текстовое содержимое счетчика.
export interface IHeaderState {
    counter: number; // текущее количество товаров в корзине
}

Конструктор:
`constructor(container: HTMLElement, events: IEvents)` — принимает контейнер шапки (.header) и объект брокера событий для инициализации слушателей. Находит внутри контейнера кнопку корзины и элемент счётчика. Устанавливает обработчик клика на кнопку корзины, который вызывает событие basket:open.

Поля класса:
`basketButton: HTMLButtonElement` — элемент кнопки корзины для установки обработчика событий.
`counterElement: HTMLElement` — HTML-элемент внутри кнопки корзины, в котором отображается счётчик.

Методы класса:
`set counter(value: number): void` — обновляет текстовое содержимое элемента counterElement, отображая текущее количество товаров в корзине.

#### Класс Gallery
Отображает каталог товаров на главной странице. Отвечает за вывод карточек. Получает готовые DOM-элементы карточек от Презентера и вставляет их в разметку.
Наследуется от базового класса Component.

Данные:
Галерея на главной странице принимает массив уже готовых к выводу DOM-элементов.
export interface IGalleryState {
    catalog: HTMLElement[]; // Массив сверстанных карточек товаров для отображения в сетке
}

Конструктор:
`constructor(container: HTMLElement)` — принимает корневой контейнер галереи (селектор .gallery) и передает его в родительский класс через super(container).

Поля класса:
`catalogElement: HTMLElement` — ссылка на элемент галереи, куда будут вставляться карточки.

Методы класса:
`set catalog(items: HTMLElement[]): void` — очищает текущее содержимое контейнера и вставляет в него новый массив элементов карточек товаров.

#### Базовый класс Card
Базовый компонент карточки товара. Содержит общие для всех типов карточек элементы: заголовок и цену.
Наследуется от Component.

Данные:
Базовый класс Card и его дочерние элементы используют единую структуру данных, но каждый дочерний класс выбирает только необходимые для своего контекста поля.
interface ICardState {
    id: string;           // Уникальный идентификатор товара
    title: string;        // Название товара
    category: string;     // Категория товара (например, "софт-скиллы")
    price: number | null; // Цена в синапсах (null отображается как "Бесценно")
    image: string;        // Ссылка на картинку товара
    text: string;         // Полное описание (используется в модальном окне)
    index: number;        // Порядковый номер товара (используется в корзине)
}

Конструктор:
`constructor(container: HTMLElement)` — находит общие элементы (.card__title, .card__price) и сохраняет их в полях.

Поля класса:
`titleElement: HTMLElement` — элемент заголовка.
`priceElement: HTMLElement` — элемент цены.

Методы класса:
`set title(value: string): void` — устанавливает текст заголовка.
`set price(value: number | null): void` — устанавливает текст цены (если null, выводит «Бесценно»).

#### Дочерний класс CardCatalog

Методы класса:
`set category(value: string): void` — устанавливает текст и цвет фона категории.
`set image(value: string): void` — устанавливает ссылку на картинку товара.

#### Дочерний класс CardPreview
Полное отображение карточки в модальном окне (#card-preview). Имеет кнопку добавления в корзину.
Наследуется от Card.

Конструктор:
`constructor(container: HTMLElement, actions?: { onClick: () => void })` — вызывает родительский конструктор, находит элементы категории, карттнки, описания и кнопку. Вешает слушатель клика на кнопку корзины.

Методы класса:

`set text(value: string): void` — устанавливает текст описания товара.

#### Дочерний класс CardBasket
Отвечает за отображение товара внутри корзины. Умеет выводить порядковый номер и реагировать на кнопку удаления.
Наследуется от Card.

Конструктор:
`constructor(container: HTMLElement, actions?: { onDelete: () => void })` — вызывает родительский конструктор, находит элемент порядкового номера и кнопку удаления. Вешает слушатель клика на кнопку удаления.

Поля класса:

Методы класса:
`set index(value: number): void` — устанавливает порядковый номер в корзине.

#### Класс Modal
Универсальный компонент модального окна. Отвечает за открытие и закрытие модального окна, управление оверлеем и установку контента внутрь себя.
Наследуется от базового класса Component.

Конструктор:
`constructor(container: HTMLElement, events: IEvents)` — принимает элемент модального окна и брокер событий. Находит кнопку закрытия и контейнер для контента. Навешивает слушатели: на кнопку закрытия, на клик по оверлею для закрытия при клике вне окна и на остановку всплытия клика внутри самого окна, чтобы оно не закрывалось при клике по контенту.

Поля класса:
`closeButton: HTMLButtonElement` — кнопка-крестик для закрытия модального окна.
`contentElement: HTMLElement` — элемент-контейнер, куда вставляется динамическая разметка.

Методы класса:
`set content(value: HTMLElement): void` — заменяет текущее содержимое contentElement на переданный DOM-элемент.
`open(): void` — открывает модальное окно, добавляя CSS-класс modal_active, и генерирует событие modal:open.
`close(): void` — закрывает модальное окно, удаляя CSS-класс modal_active, очищает контент и генерирует событие modal:close.

#### Базовый класс Form
Родительский компонент для работы с HTML-формами приложения. 
Наследуется от Component.

Данные:
interface IFormState {
    valid: boolean;     // true — кнопка отправки активна, false — заблокирована
    errors: string[];   // Массив текстовых сообщений об ошибках валидации полей

Конструктор:
`constructor(container: HTMLFormElement, events: IEvents)` — принимает элемент формы и брокер событий. Находит кнопку отправки и элемент для ошибок. Навешивает общие слушатели событий: input на всю форму для автоматического сбора изменений из любых полей и submit для предотвращения перезагрузки страницы и отправки события в Презентер.

Поля класса:
`submitButton: HTMLButtonElement` — кнопка подтверждения.
`errorsElement: HTMLElement` — элемент для отображения текста ошибок.

Методы класса:
`set valid(value: boolean): void` — управляет атрибутом disabled у кнопки отправки. Если форма невалидна — кнопка блокируется.
`set errors(value: string[]): void` — принимает массив ошибок валидации и выводит их в элемент errorsElement, объединяя строки через запятую.
`clear(): void` — сбрасывает все введенные значения в полях формы до исходных.

interface IOrderFormState extends IFormState {

Конструктор:

Поля класса:
`cardButton: HTMLButtonElement` — кнопка выбора оплаты онлайн.
`cashButton: HTMLButtonElement` — кнопка выбора оплаты при получении.

Методы класса:
`set payment(value: 'card' | 'cash' | null): void` — активирует модификатор button_alt-active на выбранной кнопке оплаты и снимает его с противоположной.

#### Дочерний класс ContactsForm
Отвечает за отображение второй формы заказа (#contacts), где пользователь заполняет свои контактные данные (Email и Телефон).
Наследуется напрямую от Form.

Данные:
interface IContactsFormState extends IFormState {
    email: string; // Значение поля Email
    phone: string; // Значение поля Телефон
}

Конструктор:
`constructor(container: HTMLFormElement, events: IEvents)` — вызывает родительский конструктор. В этой форме нет уникальных интерактивных элементов кроме стандартных полей ввода и кнопки отправки, которые уже полностью контролируются родителем.

#### Класс Basket
Компонент отображения корзины товаров. Отвечает за вывод списка выбранных товаров, отображение суммарной стоимости и активацию кнопки «Оформить». Сам список формируется из готовых DOM-строк (которые ему передает Презентер, используя ранее созданный нами класс CardBasket).
Наследуется от Component.

Данные:
interface IBasketState {
    items: HTMLElement[]; // Массив готовых DOM-строк товаров (объектов CardBasket)
    total: number;        // Общая сумма заказа для вывода на экран
}

Конструктор:
`constructor(container: HTMLElement, events: IEvents)` — принимает контейнер корзины и брокер событий. Находит список товаров, элемент общей стоимости и кнопку оформления. Навешивает слушатель клика на кнопку «Оформить» для генерации события order:open.

Поля класса:
`listElement: HTMLElement` — HTML-список, куда вставляются строки товаров.
`priceElement: HTMLElement` — элемент для вывода суммарной стоимости заказа.
`buttonElement: HTMLButtonElement` — кнопка перехода к оформлению заказа.

Методы класса:
`set items(items: HTMLElement[]): void` — принимает массив готовых элементов карточек для корзины. Если корзина пуста, выводит заглушку и блокирует кнопку оформления.
`set total(value: number): void` — обновляет текстовое содержимое элемента priceElement, выводя итоговую сумму.

#### Класс Success
Компонент окна успешного завершения заказа. Отвечает за отображение информации о том, сколько было списано, и за закрытие окна по кнопке «За новыми покупками!».
Наследуется от Component.

Данные:
interface ISuccessState {
    total: number; // Количество списанных за покупку синапсов (приходит с сервера)
}

Конструктор:
`constructor(container: HTMLElement, actions?: { onClick: () => void })` — принимает контейнер окна успешного заказа и объект с коллбэком. Находит кнопку закрытия и элемент описания. Навешивает слушатель клика на кнопку закрытия.

Поля класса:
`descriptionElement: HTMLElement` — элемент для вывода текста со списанной суммой.
`closeButton: HTMLButtonElement` — кнопка закрытия окна.

Методы класса:
`set total(value: number): void` — устанавливает текст с количеством списанных за покупку синапсов.

## Список событий и колбэков в приложении (Event / Actions Registry)

Взаимодействие слоев представления (View) и данных (Model) осуществляется с помощью брокера событий (`EventEmitter`) и передачи функций-колбэков (`actions`) в конструкторы компонентов. 

Ниже приведен актуальный список событий, генерируемых компонентами интерфейса при действиях пользователя.

### 1. События, генерируемые через брокер событий (EventEmitter)

| Название события | Источник (Компонент) | Описание события |
| :--- | :--- | :--- |
| `basket:open` | `Header` | Инициируется при клике на кнопку корзины в шапке сайта. Сигнализирует Презентеру о необходимости открыть модальное окно с корзиной. |
| `order:open` | `Basket` | Инициируется при клике на кнопку «Оформить» внутри корзины. Сигнализирует Презентеру о том, что пользователь переходит к первому шагу оформления заказа (выбор оплаты и адреса). |
| `[form_name].[input_name]:change` | `Form` (базовый) | Генерируется автоматически при вводе данных в любое поле формы (например, `order.address:change` или `contacts.email:change`). Передает объект `{ field: string, value: string }`. |
| `[form_name]:submit` | `Form` (базовый) | Генерируется при сабмите формы (например, `order:submit` на первом шаге или `contacts:submit` на втором). Сигнализирует Презентеру о необходимости валидации/отправки шага. |
| `order.payment:change` | `OrderForm` | Инициируется при клике на одну из кнопок выбора способа оплаты. Передает объект с типом платежа `{ type: 'card' \| 'cash' }`. |
| `modal:open` | `Modal` | Генерируется в момент вызова метода `open()`. Сигнализирует Презентеру о том, что модальное окно перешло в активное состояние (например, для блокировки прокрутки страницы). |
| `modal:close` | `Modal` | Генерируется в момент вызова метода `close()`. Сигнализирует Презентеру о закрытии окна и очистке текущего контекста отображения. |
| `items:changed` | `CatalogModel` | Инициируется при успешной установке массива товаров (например, после загрузки с сервера). Уведомляет Презентер о необходимости перерисовать главную витрину `Gallery`. |
| `preview:changed` | `CatalogModel` | Инициируется при выборе товара для детального осмотра. Передает данные выбранного товара в Презентер для последующего рендера в `CardPreview` внутри модалки. |
| `basket:changed` | `BasketModel` | Инициируется при любом изменении состава корзины (добавление, удаление, очистка). Сигнализирует о необходимости обновить счётчик в `Header` и пересчитать сумму в `Basket`. |
| `buyer:form-errors` | `BuyerModel` | Генерируется при изменении полей данных покупателя. Передает объект с текущими ошибками валидации `FormErrors`. Позволяет Презентеру динамически блокировать или разблокировать кнопку «Далее» / «Оплатить» во View-формах. |

### 2. Прямые обработчики действий пользователя (Колбэки/Actions)

Некоторые компоненты не вызывают события брокера напрямую, а выполняют переданные им при создании функции-колбэки. Это позволяет изолировать дочерние компоненты (например, карточки) от глобального брокера.

| Компонент | Колбэк (Параметр) | Описание поведения |
| :--- | :--- | :--- |
| `Gallery` | *Отсутствуют* | Компонент является чисто реактивным контейнером для готовой разметки и не обрабатывает пользовательский ввод напрямую. |
| `CardCatalog` | `onClick: () => void` | Вызывается при клике на любое место контейнера карточки на витрине. Передаёт сигнал Презентеру для открытия модального окна предварительного просмотра (`CardPreview`). |
| `CardPreview` | `onClick: () => void` | Вызывается при клике на кнопку внутри окна детального просмотра (кнопка «В корзину»). Передаёт сигнал Презентеру для добавления товара в модель корзины. |
| `CardBasket` | `onDelete: () => void` | Вызывается при клике на кнопку-иконку удаления (корзину) в строке товара. Сигнализирует Презентеру о необходимости удалить данный товар из модели корзины. |
| `Success` | `onClick: () => void` | Вызывается при клике на кнопку «За новыми покупками!» в окне успешного завершения заказа. Сигнализирует Презентеру о необходимости закрыть модальное окно и полностью обнулить состояние приложения (очистить корзину, сбросить формы) для нового цикла покупок. |

## Архитектурный слой: Презентер (Связующий слой)

Презентер не выделяется в отдельный класс, а реализуется в главном скрипте приложения `src/main.ts`. Его основная задача — управление взаимодействием между Моделями данных (Model) и Компонентами представления (View) с помощью событийно-ориентированного подхода.

### Принципы работы Презентера:
1. **Реактивность:** Презентер никогда не вызывает принудительный перерендер интерфейса сразу после вызова методов изменения данных в модели. Перерисовка View происходит строго в ответ на события, генерируемые Моделями после того, как данные внутри них были успешно изменены.
2. **Изоляция:** Компоненты View и Model ничего не знают друг о друге. Их общение инкапсулировано внутри обработчиков событий Презентера.
3. **Отсутствие генерации:** Презентер только слушает (`events.on`) и обрабатывает события. Сам Презентер новые события в брокер не отправляет.
